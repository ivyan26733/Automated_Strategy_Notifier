KEY FINDINGS
======================================================================

FINDING 1: EMA SEED METHOD
  Python uses  : SMA of first [period] weekly closes as seed
  TradingView  : first weekly close = seed (Pine Script ta.ema)
  Impact       : negligible for stocks with 200+ weekly bars (>4yr data)
  Stocks where seed FLIPS above/below: 2
  These stocks have borderline EMA9≈EMA20 AND short history.

FINDING 2: DEVELOPING WEEK CONSTRUCTION
  Python build_weekly() correctly uses latest daily close as
  developing week Close — matching TradingView's developing bar.
  Week keyed by ISO Monday → correct for NSE Mon-Fri sessions.

FINDING 3: CROSSOVER STATE VARIABLE
  EmaCrossoverStrategy.above starts as False each scan, which
  correctly prevents emitting a signal when EMA9 was already >
  EMA20 at the first valid EMA20 bar (bar index 19).
  No false positives from state initialization. ✓

FINDING 4: SIGNAL DEDUPLICATION KEY
  Upsert key: (strategy_name, symbol, signal_date, signal_type)
  signal_date = observation_date (latest DAILY close, not Mon)
  Risk: If the scanner runs on Mon and records a developing-week
  golden cross, then on Tue prices reverse → Mon signal stays in DB.
  Frontend's activeSet check filters this out correctly. ✓

FINDING 5: SCANNER MUST RUN DAILY POST-MARKET
  The developing-week EMA is recalculated each day using that
  day's close. A crossover occurring on any day Mon-Fri is only
  captured if the scanner runs on that day (or later the same week).
  Crossovers that appear intra-week and reverse before Friday are
  captured with the day's signal_date but persist in DB unless
  you implement signal invalidation.

FINDING 6: STALE DEVELOPING-WEEK SIGNALS IN DB
  Each day the scanner runs, the developing week's obs_date changes.
  Upsert key includes signal_date, so Mon's cross (date=Mon) and
  Tue's cross (date=Tue if still active) are SEPARATE DB rows.
  Old developing-week signal rows (e.g. Mon) are never deleted.
  Frontend's 28-day + activeSet filter handles this correctly. ✓
